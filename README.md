# Как угодно

Адаптивный веб-мессенджер на Node.js, Express, MongoDB, Socket.IO и WebRTC.

## Возможности

- Регистрация по уникальному никнейму и паролю; аватар необязателен.
- Хеширование паролей через bcryptjs и авторизация с JWT.
- Поиск пользователей, публичная карточка профиля и запросы обмена контактами.
- Всплывающее уведомление о запросе контакта с индикатором обратного отсчёта на 5 секунд. Сам запрос хранится в MongoDB, пока адресат не примет или не отклонит его.
- Личные переписки в реальном времени через Socket.IO.
- Сообщения, ответы, пересылка, редактирование и удаление собственного сообщения, реакции.
- Аудио- и видеозвонки на WebRTC. Сигнализация идёт через Socket.IO, медиапоток — напрямую между браузерами при возможности.
- Проверка состояния сервиса на `/api/health`.

## Локальный запуск

Требуется Node.js 22+ и MongoDB (локально или MongoDB Atlas).

1. Установи зависимости: `npm install`.
2. Скопируй `.env.example` в `.env`.
3. Укажи `MONGODB_URI` и сгенерируй `JWT_SECRET` длиной не менее 32 символов.
4. Запусти `npm run dev`.
5. Открой `http://localhost:3000`.

На localhost браузеры разрешают WebRTC-медиа в контексте разработки. На опубликованном сайте используй HTTPS.

## MongoDB Atlas

1. Создай проект и кластер в MongoDB Atlas.
2. Создай отдельного Database User с сильным паролем. Это не тот же пароль, что у твоего аккаунта Atlas.
3. В разделе Network Access добавь правило доступа для исходящего адреса Render. Для первичного теста можно временно разрешить `0.0.0.0/0`, но это открывает сетевой доступ со всего интернета: используй сильные учётные данные базы и не оставляй такое правило без необходимости. Для production ограничь доступ известными исходящими IP-адресами или используй приватное сетевое подключение, если оно доступно в твоём тарифе.
4. Нажми Connect → Drivers и скопируй connection string. Замени имя пользователя, пароль и добавь имя базы `kakugodno` в адрес, например: `mongodb+srv://USER:PASSWORD@cluster.example.mongodb.net/kakugodno?retryWrites=true&w=majority`.
5. Если пароль содержит специальные символы, URL-кодируй их в connection string.

## Развёртывание на Render

В репозитории уже есть `render.yaml`. Бесплатный Web Service подходит для первого тестирования, но Render может усыпить его после 15 минут без входящих HTTP-запросов и WebSocket-сообщений; следующий запрос разбудит сервис, поэтому первая загрузка может занять около минуты. Пока пользователь авторизован и открыт мессенджер, клиент отправляет heartbeat раз в 5 минут. Для постоянно доступного продакшен-мессенджера лучше выбрать платный план Render.

### Вариант A — через Blueprint (проще)

1. Запушь ветку `main` в GitHub.
2. В Render открой **New → Blueprint** и подключи репозиторий `projecterariel676767-web/Kakugodno`.
3. Render прочитает `render.yaml`. На первом создании введи значение `MONGODB_URI` из Atlas. Render сгенерирует `JWT_SECRET`.
4. Нажми Apply. Дождись успешного deploy.
5. Открой адрес сервиса вида `https://kakugodno.onrender.com/api/health`. Ответ должен содержать `"ok": true` и `"database": "connected"`.

### Вариант B — вручную

Создай **Web Service** из GitHub-репозитория и укажи:

| Настройка | Значение |
|---|---|
| Runtime | Node |
| Branch | `main` |
| Build Command | `npm install` |
| Start Command | `npm start` |
| Health Check Path | `/api/health` |

В **Environment** добавь:

| Key | Value |
|---|---|
| `NODE_ENV` | `production` |
| `MONGODB_URI` | connection string из MongoDB Atlas |
| `JWT_SECRET` | длинная случайная строка, минимум 32 символа |
| `TURN_URL` | необязательно: URL TURN-сервера |
| `TURN_USERNAME` | необязательно: имя пользователя TURN |
| `TURN_CREDENTIAL` | необязательно: пароль/credential TURN |

Не помещай реальные пароли и секреты в GitHub. Добавляй их только в Environment на Render.

## Звонки

Сайт использует WebRTC и общедоступные STUN-серверы как базовую конфигурацию. В простых сетевых условиях этого может хватить, но STUN не гарантирует соединение между любыми сетями. Для надёжной связи через строгий NAT/firewall подключи TURN-провайдера и задай `TURN_URL`, `TURN_USERNAME`, `TURN_CREDENTIAL` в Render. Сервер отдаёт ICE-конфигурацию только авторизованному пользователю.

Звонки требуют HTTPS и разрешения браузера на микрофон/камеру. Проверяй их с двух разных устройств/сетей. Для групповых звонков текущая реализация не предназначена.

## Заметки о хранении

Профиль, запросы контактов, сообщения, ответы, пересылки и реакции хранятся в MongoDB. Аватары сейчас сохраняются как небольшие Data URL в документе пользователя (лимит загрузки — 500 КБ). Для крупного масштаба лучше вынести аватары в объектное хранилище и сохранить в MongoDB только URL.
